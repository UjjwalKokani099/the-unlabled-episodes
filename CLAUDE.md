# UNLABELED — project notes

First-person found-footage horror game. Godot 4.7.2, GDScript, Forward+, Jolt physics.
The owner is a React developer new to Godot: all scenes (.tscn), resources (.tres) and
settings are written as text files, not built in the editor.

## Story and current brief
- `docs/story.md` is the story bible: source of truth for names, dates, places, rules.
- `docs/brief_visuals_and_demo.md` is the active brief (visual upgrade + demo).

- Run a scene for N frames and capture errors:
  `<console exe> --path . --quit-after 300 res://scenes/test/<scene>.tscn`
- Syntax-check a script: `<console exe> --headless --path . --check-only --script res://path.gd`
- Run all automated tests: `bash tests/run_tests.sh` (opens a window per test; mouse capture
  needs a real window). Tests are SceneTree scripts in `tests/test_*.gd` that print PASS/FAIL.
  They must not use class_name types or autoload names at compile time (untyped `var p`):
  `--script` compiles them before autoloads are registered.

## Gotchas found so far
- AnimatableBody3D only syncs collision when its *own* transform changes — make the moving
  node the body itself (see `scenes/props/door.tscn`), don't rotate a parent of it.
- Physics layers: 1 world, 2 player, 3 interactable (value 4). The Interactor ray masks 1|4.
- HUD messages from anywhere: `get_tree().call_group("hud", "show_message", "text")`.
- Test scripts: `await process_frame` before touching autoloads (their `_ready` hasn't run
  yet in `_initialize`).

## Gameplay wiring (Events + Objectives)
- `Events.fire(&"id")` announces anything; Pickups fire their `item_id`, Doors fire
  `opened_event`, completed objectives fire their own `id`.
- A level's objectives are an `ObjectiveSet` .tres (see `scenes/test/test_objectives.tres`)
  loaded by an `ObjectiveLoader` node. Each objective: `complete_on` event, `required`
  count, `starts_after` objective id.
- Props react to events via exports, e.g. Door `unlock_event = &"find_tape"`.
- Scares = `TriggerZone` (fires `event_id` on player enter; `armed_by` gates it) plus
  `EventReaction` nodes listening to that id with their own `delay`: FlickerReaction,
  SoundReaction, VisibilityReaction, MethodReaction (calls any method, e.g. Door `slam`).
  Example: the `Scares` node in `scenes/test/test_room.tscn`.
- Flicker lights by `light_energy`, never `visible` (visible = the player's on/off state).
- Placeholder SFX come from `python tools/gen_placeholder_sfx.py`; replace files in place.

## Chapters / saving (Game autoload)
- `chapters/chapter_list.tres` lists the tapes in order (+ debug chapters, hub scene).
  Each tape has `chapters/<tape>/chapter.tres` (title, scene_path, camcorder start time);
  empty scene_path = not built yet. Test chapter: `scenes/test/test_chapter.tres`.
- `Game.start_chapter(id)`, `load_checkpoint()`, `restart_chapter()`, `complete_chapter()`
  (end a level with a MethodReaction targeting `/root/Game`). Save: `user://save.json`.
- A level needs: Player, HUD, Camcorder, ObjectiveLoader, and `Checkpoint` areas (origin on
  the floor, respawn faces -Z; one at the spawn so Continue works immediately).
- Checkpoint = Events counts + Game flags + camcorder time. Anything that must survive a
  reload is either derived from Events counts or stored with `Game.set_flag()` (Pickups do).
  While objectives rebuild, `Events.replaying` is true and EventReactions ignore events.

## Hub (scenes/hub/hub.tscn = main scene for now)
- Shelf of `HubTape`s (chapter_id each; blank sticker = locked, red dot = watched). Picked
  tape is reparented to a Hand node on the camera; VCR inserts it -> `Game.start_chapter`,
  or resumes the checkpoint when empty-handed. `Game.return_to_hub()` leaves a tape early.
- Hub geometry is generated by a script; edit `scenes/hub/hub.tscn` directly from now on.
- Disabled Interactables leave the physics layer, so they never block the look-ray.

## Menus
- Main scene = `scenes/menus/main_menu.tscn` (Continue / Start|Tapes / New game / Settings /
  Quit). Pause menu lives inside `ui/hud/hud.tscn`, so any level with the HUD has it (Esc).
- `ui/menus/settings_menu.tscn` is shared; its rows come from `ROWS` in settings_menu.gd —
  add a Settings var + KEYS entry + one ROWS line for a new option.
- Theme for all menus: `ui/themes/vcr_theme.tres`. Button lists use `MenuList` (hover moves
  focus, beeps). Pause/menus use process_mode Always; Game pauses the tree during loads.
- Brightness is a gamma overlay owned by the Settings autoload (canvas layer 5).

## Graphics / performance (target: 60 FPS at 1080p on the RTX 3050 Ti laptop)
- `Graphics` autoload applies Low/Medium/High (`PRESETS` in scripts/autoload/graphics.gd):
  render scale, FXAA, LOD threshold, shadow quality, SSAO/SSIL/volumetric-fog quality.
- Levels author their WorldEnvironment with the features they want (AgX tonemap, SSAO,
  SSIL, glow, volumetric fog); presets only switch features off, never add them.
- Benchmark: `<console exe> --path . --script res://tools/benchmark.gd -- <scene> [sec]`
  (fullscreen, VSync off; visits Marker3Ds in group `benchmark_points`). Run it after every
  visual change and report avg / 1% low / GPU ms per preset.
- Lighting plan: baked LightmapGI for static light (owner presses Bake in the editor),
  real-time lights only for flicker / flashlight / power cut.

## Materials and decals (Phase 1)
- `shaders/surfaces/surface.gdshader` = THE wall/floor shader: world-space projection (no UVs,
  `tile_size` in metres), macro variation, per-storey weathering (rising damp + tide line,
  leak streaks from under slabs, top grime) and a two-tone dado band. Storeys are 3 m.
- Library: `assets/materials/*.tres`, generated from the table in `tools/gen_materials.py`
  (edit the table, re-run; don't hand-edit the .tres). Textures: CC0 ambientCG via
  `tools/fetch_textures.py` (credits in assets/materials/CREDITS.md).
- After adding any texture: `--import`, `python tools/configure_texture_imports.py`,
  `--import` again (VRAM compression + mipmaps + normal-map flag).
- Imported normal maps are 2-channel (RG): custom shaders must rebuild Z themselves.
- Decals: `scenes/decals/<name>.tscn` — place the node ON the surface with +Z pointing out
  of it. Posters come from `tools/gen_posters.gd` (Godot renders Devanagari) then
  `tools/gen_decals.py` ages them and draws stains/cracks.
- Preview everything in `scenes/test/material_gallery.tscn` (built by
  `tools/gen_material_gallery.py`). Tube light fixture: `scenes/props/tube_light.tscn`.

## Building kit (Phase 2)
- `tools/levelkit.py` = the modular kit as Python functions (wall with openings, slab,
  stair_flight, railing, window_fill, residential_wing, sodium_lamp, night_environment,
  player_rig). Level generators (`tools/gen_*.py`) import it and write .tscn files.
- Static geometry goes under `Static` (StaticBatcher merges it at runtime: ~1500 boxes ->
  ~40 meshes per wing); collision under one `Collision` StaticBody3D. Stairs = visual steps
  + convex ramp collider. Doors/props that move stay outside `Static`.
- Closed flats get BoxOccluder3D occluders (occlusion culling is on).
- Preview: `scenes/test/kit_preview.tscn` (`python tools/gen_kit_preview.py`).

## Camera / screen
- Every level instances `ui/hud/camcorder.tscn` (OSD on layer 2, VHS shader on layer 3) and
  `ui/hud/hud.tscn` (layer 10, stays crisp above the VHS effect). Debug overlay = layer 20.
- Shake: `call_group("camera_shake", "add_trauma", x)`; glitch: `call_group("camcorder",
  "glitch", amount, seconds)`; or a `CameraReaction` node. CameraShake owns the camera's
  local rotation — don't set Camera3D.rotation elsewhere.
- 3D renders at 75% (`rendering/scaling_3d/scale`) for the lo-fi look and performance.
- Tests: frame rate is uncapped under `--script`; wait real seconds for timing checks, and
  free the level before quit() (sounds still playing at exit report leaks).

## Layout
- `scenes/`   hub, menus, test scenes
- `scripts/`  autoload (singletons), player, interaction, objectives, events, ui
- `chapters/` one folder per tape: scene + chapter-specific scripts/data
- `shaders/`  .gdshader files (lo-fi / VHS post-processing)
- `ui/`       themes and HUD scenes
- `assets/`   models, textures, audio, fonts (binary files tracked by Git LFS)

## Conventions
- Systems shared across chapters live in `scripts/` and are reused, never copied into chapters.
- Keep it light (target: RTX 3050 Ti laptop): low-poly, few real-time lights, simple shaders.
- One commit per working system.
